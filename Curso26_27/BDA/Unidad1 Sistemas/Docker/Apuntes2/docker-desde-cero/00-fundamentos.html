Que es Docker y por que existe

Antes de instalar nada: que problema resuelve Docker de verdad, que es un contenedor, que es una imagen, y por que estas dos palabras no son lo mismo aunque se usen mezcladas todo el rato.

1. El problema que Docker resuelve

Imagina que escribes una aplicacion que necesita Python 3.11, una version concreta de una libreria, y una base de datos PostgreSQL 15 arrancada. Funciona perfecto en tu ordenador. Se la pasas a un companero, y no le arranca: el tiene Python 3.9, otra version de la libreria, y ni siquiera tiene PostgreSQL instalado. Ese problema tiene nombre entre programadores: "en mi maquina funciona". No es una excusa — es un sintoma real de que el entorno donde corre el codigo no esta descrito en ningun sitio, solo vive a mano en tu ordenador.

Sin Docker
  • Cada maquina tiene su propia mezcla de versiones instaladas a mano.
  • Instalar el proyecto en una maquina nueva significa seguir una lista de pasos (a veces desactualizada) y rezar.
  • "Funciona en mi maquina" no es una solucion, es un chiste que esconde horas perdidas.
Con Docker
  • El entorno completo (sistema operativo base, dependencias, version exacta de cada cosa) queda descrito en un fichero de texto.
  • Ese fichero se ejecuta igual en tu maquina, en la de tu companero, o en un servidor en la nube.
  • "Funciona en mi maquina" deja de ser relevante porque todos corren literalmente el mismo entorno empaquetado.

2. Contenedor no es lo mismo que maquina virtual

Es la confusion mas comun al empezar. Una maquina virtual (VM) simula un ordenador entero, con su propio sistema operativo completo por dentro — pesa gigas, tarda minutos en arrancar. Un contenedor es mucho mas ligero: comparte el kernel del sistema operativo del host y solo aisla los procesos, los ficheros y la red de la aplicacion. Por eso un contenedor pesa megas, no gigas, y arranca en menos de un segundo en vez de minutos.

VM

Maquina virtual

Simula hardware completo + un sistema operativo entero por dentro. Aislamiento total, pero pesado y lento de arrancar.

DOC

Contenedor Docker

Comparte el kernel del host, aisla solo procesos y ficheros. Ligero, arranca en milisegundos, pero no es aislamiento a nivel de hardware.

INFO
Por eso Docker solo existe de verdad en Linux (comparte el kernel Linux). En Mac y Windows, Docker Desktop arranca una pequena maquina virtual Linux por debajo, sin que lo notes, para poder compartir kernel con los contenedores. Es un detalle que rara vez importa dia a dia, pero explica por que algunos comportamientos (rutas de fichero, rendimiento de volumenes) son ligeramente distintos entre Linux nativo y Mac/Windows.

3. Imagen y contenedor no son la misma palabra

Esta es la segunda confusion mas comun, y vale la pena fijarla con una analogia concreta antes de seguir.

Imagen

Es la receta empaquetada: un fichero (en realidad varias capas apiladas) que describe que sistema base usar, que instalar, que ficheros copiar y que comando ejecutar al final. No esta "corriendo" — es una plantilla estatica, guardada en disco.

Contenedor

Es una imagen puesta en marcha: un proceso real corriendo, con su propio sistema de ficheros aislado (basado en la imagen) y su propia red. De la misma imagen puedes arrancar cero, uno o cien contenedores distintos, todos independientes entre si.

Dicho de otra forma: la imagen es la clase, el contenedor es el objeto instanciado. O, si prefieres cocina: la imagen es la receta escrita, el contenedor es el plato ya cocinado y servido — puedes cocinar el mismo plato (imagen) tantas veces como quieras (contenedores), y cada uno es independiente aunque venga de la misma receta.

4. Tu primer contenedor de verdad, y que hace cada palabra del comando

Antes de explicar mas teoria, ejecuta esto. Es el "hola mundo" oficial de Docker.

bash - Primer contenedor 
docker run hello-world

Lo que ocurre por dentro, paso a paso:

1
Docker busca la imagen hello-world en tu maquina

La primera vez no esta — no la has descargado nunca.

2
Como no la encuentra local, la descarga de Docker Hub

Docker Hub es un registro publico de imagenes en internet — como un GitHub, pero de imagenes en vez de codigo. Veras la linea Unable to find image 'hello-world:latest' locally seguida de la descarga.

3
Docker crea un contenedor nuevo a partir de esa imagen y lo arranca

El proceso dentro del contenedor imprime un mensaje explicando lo que acaba de pasar, y termina.

4
El contenedor termina y queda parado (no se borra solo)

Si ejecutas docker ps -a (el -a es importante — sin el solo ves los que siguen corriendo) lo veras ahi, con estado Exited.

Repite el comando una segunda vez y compara: ya no aparece la linea de descarga, porque la imagen ya esta en tu maquina — solo se crea y arranca un contenedor nuevo, al instante.

5. Un detalle que te va a sonar raro luego: cliente y daemon

Cuando escribes docker run ..., esa orden en realidad viaja a un proceso de fondo llamado daemon, que es quien hace el trabajo real. Lo que tecleas es solo el cliente, un mensajero. No necesitas hacer nada distinto por esto — sigue escribiendo docker run igual — pero cuando mas adelante veas la palabra dockerd en un log de error, ya sabras que es el nombre de ese proceso de fondo, no un typo.

6. Vocabulario minimo para el resto del curso

Palabra Que es
Imagen Plantilla estatica en disco: sistema base + dependencias + ficheros + comando por defecto.
Contenedor Una imagen puesta en marcha: un proceso real, aislado, corriendo ahora mismo (o parado tras terminar).
Dockerfile El fichero de texto donde describes como se construye una imagen, paso a paso.
Registro (registry) Un almacen de imagenes al que hacer push/pull. Docker Hub es el publico y gratuito por defecto.
Daemon (dockerd) El proceso de fondo que gestiona todo de verdad. El comando docker es solo el cliente que le habla.
Docker Hub El registro publico oficial — de ahi sale hello-world, python, mariadb y miles de imagenes mas.

7. Idea central del capitulo

  • Docker no virtualiza un ordenador entero — aisla procesos compartiendo el kernel del host, por eso es ligero y rapido.
  • Imagen = plantilla estatica. Contenedor = esa plantilla puesta en marcha. No son sinonimos.
  • Tu nunca hablas directamente con los contenedores: el cliente docker siempre pasa por el daemon.
  • A partir de aqui, cada capitulo profundiza en una pieza: instalar y correr contenedores de verdad, construir tus propias imagenes, guardar datos, conectar contenedores entre si, y orquestar varios a la vez con Compose.
