03

Ver dentro de un contenedor vivo

Tu contenedor esta corriendo en segundo plano. ¿Como sabes que hace? ¿Como entras a mirar sin pararlo? ¿Como le pasas configuracion sin reconstruir la imagen?

1. Ver los logs — que esta imprimiendo el contenedor

bash - Logs 
docker logs mi_nginx        # todo lo que ha impreso desde que arranco
docker logs -f mi_nginx     # lo mismo, pero se queda mirando en vivo (Ctrl+C para salir)

Todo lo que el proceso principal del contenedor escribe por su salida estandar (lo que verias en tu terminal si lo hubieras arrancado a mano) queda capturado aqui. Es el primer sitio donde mirar cuando algo no funciona.

2. Entrar en un contenedor que ya esta corriendo

Esto es distinto de docker run -it del capitulo anterior. run siempre crea un contenedor NUEVO. Si ya tienes uno corriendo y quieres asomarte dentro, usas exec:

bash - Entrar en un contenedor vivo 
docker exec -it mi_nginx bash
WARN
Confusion tipica: ejecutar docker run -it mi_nginx bash pensando que vas a entrar en el contenedor que ya corre — en realidad acabas de crear uno SEGUNDO, nuevo y distinto, con el mismo nombre de imagen pero sin nada de lo que hiciste en el primero. Si quieres el que ya existe, es exec, no run.

3. Configurar sin reconstruir: variables de entorno

Muchas imagenes se configuran con variables de entorno en vez de ficheros. Por ejemplo, la imagen oficial de MariaDB usa MARIADB_ROOT_PASSWORD para fijar la contrasena de root al arrancar:

bash - Variables de entorno con -e 
docker run -d --name mi_bd \
  -e MARIADB_ROOT_PASSWORD=secreto123 \
  -e MARIADB_DATABASE=miapp \
  mariadb:11.4

La ventaja frente a poner esos valores dentro de la imagen: la MISMA imagen sirve para desarrollo, pruebas y produccion — solo cambian las variables con las que la arrancas, no el contenido de la imagen.

4. Que deberia quedarte claro al cerrar este capitulo

  • docker logs -f es tu primera parada para saber que hace un contenedor por dentro.
  • exec entra en un contenedor que ya existe; run siempre crea uno nuevo — no son intercambiables.
  • -e configura el contenedor al arrancar, sin tocar la imagen — la misma imagen sirve para varios entornos distintos.
