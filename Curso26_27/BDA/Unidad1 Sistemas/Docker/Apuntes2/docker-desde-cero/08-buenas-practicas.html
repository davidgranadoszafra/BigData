Buenas practicas: imagenes mas pequenas y mas seguras

Ultimo capitulo. Todo lo anterior ya te hace funcional con Docker. Esto es lo que separa "funciona" de "funciona bien".

1. Multi-stage build: no cargues con lo que solo hizo falta para construir

Para compilar o instalar dependencias a veces necesitas herramientas (compiladores, paquetes de desarrollo) que la aplicacion YA COMPILADA no necesita para ejecutarse. Un multi-stage build usa una imagen para construir, y copia solo el resultado final a una imagen limpia:

dockerfile - Multi-stage build 
# Etapa 1: build -- aqui SI hacen falta herramientas pesadas
FROM python:3.12 AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --user --no-cache-dir -r requirements.txt

# Etapa 2: runtime -- imagen final, limpia
FROM python:3.12-slim
WORKDIR /app
COPY --from=builder /root/.local /root/.local
COPY . .
ENV PATH=/root/.local/bin:$PATH
CMD ["python", "app.py"]

La imagen final (FROM python:3.12-slim en la etapa 2) nunca tuvo el compilador completo de la etapa 1 — solo recibio, con COPY --from=builder, el resultado ya instalado. Menos peso, menos superficie de ataque, mismo resultado funcional.

2. .dockerignore: no copies lo que no hace falta

Igual que .gitignore, pero para el build. Sin el, COPY . . copia TODO lo que hay en la carpeta — incluida tu carpeta local de dependencias, tu historial de git, tus ficheros de configuracion del editor.

text - .dockerignore 
.git
.venv
__pycache__
*.pyc
.env
node_modules

3. Limpieza: Docker acumula basura si no la vacias

Imagenes intermedias, contenedores parados y viejos, redes sin usar — se van acumulando y ocupando disco.

bash - Limpieza 
docker system df       # cuanto espacio ocupa cada cosa, primero mira esto
docker system prune    # borra lo que ya no esta en uso (pide confirmacion)

4. Tres habitos de seguridad basicos, sin complicarse

No corras como root dentro del contenedor

Muchas imagenes oficiales ya definen un usuario sin privilegios — usalo (USER appuser en el Dockerfile) en vez de dejar el root por defecto.

No uses :latest en produccion

latest cambia de contenido con el tiempo sin avisar. Fija una version concreta (python:3.12.4-slim) para que el mismo Dockerfile construya siempre lo mismo.

5. Repaso del curso completo

  • Capitulo 0-1: imagen vs contenedor, y los comandos basicos del dia a dia.
  • Capitulo 2: construir tu propia imagen con un Dockerfile, y por que el orden de las capas importa.
  • Capitulo 3: operar un contenedor vivo — logs, exec, variables de entorno.
  • Capitulo 4-5: sacar los datos fuera del contenedor (volumenes) y conectar varios contenedores entre si (redes).
  • Capitulo 6-7: declarar todo eso en un solo fichero con Compose, y hacerlo robusto de verdad con healthchecks.
  • Este capitulo: imagenes mas pequenas, mas limpias y algo mas seguras.
