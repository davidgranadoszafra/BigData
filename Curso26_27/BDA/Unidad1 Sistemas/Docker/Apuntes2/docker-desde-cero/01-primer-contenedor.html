Instalacion y primer contenedor de verdad

Ya sabes que es una imagen y que es un contenedor (capitulo 0). Ahora los comandos que vas a usar todos los dias: run, ps, images, stop, rm.

1. Instalar Docker

En Mac y Windows, instala Docker Desktop desde docker.com — incluye el cliente, el daemon (dentro de una VM Linux ligera, invisible para ti) y una interfaz grafica opcional. En Linux, se instala el paquete docker.io o el repositorio oficial de Docker directamente, sin VM intermedia, porque el kernel ya es Linux.

bash - Comprobar que esta instalado y arrancado 
docker --version
docker info

docker --version solo comprueba el cliente. docker info pregunta al daemon — si esta apagado, este segundo comando falla con un error de conexion. Es la primera comprobacion que hacer cuando algo "no funciona".

2. Los tres comandos que mas vas a usar

bash - El trio basico 
docker images          # que imagenes tengo descargadas
docker ps              # que contenedores estan corriendo AHORA
docker ps -a           # todos los contenedores, incluidos los parados

El fallo tipico de quien empieza: ejecutar algo, no verlo en docker ps, y pensar que ha fallado — cuando en realidad ya termino y esta parado. Por eso docker ps -a es el que de verdad cuenta la historia completa.

3. Modo interactivo vs modo en segundo plano

Prueba estos dos comandos y compara la diferencia real, no solo la teoria:

Interactivo (-it)
docker run -it ubuntu bash

Te deja una terminal DENTRO del contenedor. Tu terminal normal queda "ocupada" hasta que escribas exit. Util para explorar o depurar.

Segundo plano (-d)
docker run -d nginx

El contenedor arranca y tu terminal queda libre al instante. Es como usaras Docker casi siempre para servicios reales (una web, una base de datos).

4. Nombrar, parar y borrar contenedores

Sin darle nombre, Docker le pone uno aleatorio (algo como relaxed_turing). Dale tu un nombre para no tener que buscarlo:

bash - Ciclo de vida con nombre propio 
docker run -d --name mi_nginx nginx
docker stop mi_nginx      # lo para, pero sigue existiendo (docker ps -a lo ve)
docker start mi_nginx     # lo vuelve a arrancar
docker rm mi_nginx        # lo borra de verdad -- tiene que estar parado antes
docker rm -f mi_nginx     # lo para Y lo borra en un solo paso

5. Publicar un puerto — para poder abrirlo en el navegador

Un contenedor tiene su propia red aislada por defecto. Si dentro corre un servidor web escuchando en el puerto 80, ese 80 no existe para tu navegador hasta que lo publicas explicitamente con -p.

bash - Publicar un puerto 
docker run -d --name web -p 8080:80 nginx

-p 8080:80 se lee de derecha a izquierda: "el puerto 80 de DENTRO del contenedor, publicalo como el puerto 8080 de tu maquina". Abre http://localhost:8080 y veras la pagina de bienvenida de nginx — sirviendose desde dentro del contenedor.

WARN
Error tipico: arrancar sin -p, ver que el contenedor esta "corriendo" en docker ps, y no entender por que localhost no responde. El contenedor esta bien — simplemente nadie le abrio la puerta hacia fuera. Compara siempre lo que dice docker ps en la columna PORTS: si esta vacia, no hay nada publicado.

6. Que deberia quedarte claro al cerrar este capitulo

  • docker ps -a cuenta la verdad completa; docker ps solo. lo que esta vivo ahora.
  • -d para servicios que se quedan corriendo, -it para entrar y toquetear.
  • Sin -p, lo que corre dentro del contenedor es invisible desde fuera, aunque el contenedor este perfectamente sano.
