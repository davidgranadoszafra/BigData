Volumenes: que pasa con tus datos

Un contenedor esta pensado para poder borrarse y recrearse sin drama. ¿Que pasa entonces con los datos que guarda dentro, como una base de datos?

1. Demuestralo tu mismo: los datos mueren con el contenedor

bash - Prueba real, en tres pasos 
docker run -it --name prueba ubuntu bash
# dentro del contenedor:
echo "dato importante" > /dato.txt
exit

docker rm prueba
docker run -it --name prueba ubuntu bash
cat /dato.txt   # No such file or directory

El fichero desaparecio porque vivia SOLO dentro del sistema de ficheros de ese contenedor concreto, y ese contenedor ya no existe. Este es el problema real que resuelven los volumenes: sacar los datos de dentro del contenedor, para que sobrevivan aunque el contenedor se borre.

2. Dos formas de guardar datos fuera del contenedor

Volumen con nombre (named volume)

Docker gestiona donde vive fisicamente. No necesitas saber la ruta exacta en tu disco — solo le pones un nombre y Docker se encarga. Es la opcion recomendada para datos de aplicacion (bases de datos, por ejemplo).

docker run -d -v mis_datos:/var/lib/mysql mysql
Bind mount

Tu decides exactamente que carpeta de TU maquina se conecta con una carpeta DENTRO del contenedor. Util para desarrollo: editas codigo en tu editor y el contenedor lo ve al instante, sin reconstruir nada.

docker run -d -v /Users/tu/proyecto:/app mi-app

En los dos casos la sintaxis es -v origen:destino — la diferencia es que en el volumen con nombre el "origen" es un nombre que Docker gestiona, y en el bind mount es una ruta real de tu disco que tu eliges.

3. Comandos para gestionar volumenes con nombre

bash - Gestion de volumenes 
docker volume ls                 # que volumenes existen
docker volume create mis_datos   # crear uno explicitamente (docker run tambien lo crea solo si no existe)
docker volume rm mis_datos       # borrarlo -- esto SI borra los datos de verdad
WARN
Diferencia importante: docker rm contenedor borra el contenedor pero NO el volumen asociado — el volumen sobrevive, listo para conectarse a un contenedor nuevo. docker volume rm es el que de verdad borra los datos. Son dos comandos distintos a proposito, para que borrar un contenedor nunca sea un accidente que te cueste datos.

4. Que deberia quedarte claro al cerrar este capitulo

  • Sin volumen, cualquier dato dentro de un contenedor desaparece cuando el contenedor se borra.
  • Volumen con nombre: Docker gestiona la ubicacion, ideal para datos de aplicacion.
  • Bind mount: tu eliges la ruta exacta del host, ideal para desarrollo.
  • Borrar un contenedor no borra sus volumenes — son ciclos de vida independientes, a proposito.
