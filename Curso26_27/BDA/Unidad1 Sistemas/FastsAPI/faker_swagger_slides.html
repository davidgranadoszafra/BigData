El dilema del huevo y la gallina en Big Data

RGPD

Privacidad Innegociable

No puedes usar datos de producción en desarrollo ni en clase. Las multas por fuga alcanzan el 4% de la facturación global.

VOLUMEN

Escala Realista

Para probar Kafka, Spark o una API necesitas miles de eventos distribuidos en el tiempo, no 3 objetos JSON escritos a mano.

EDGES

Casos Límite

Nombres con tildes, formatos de teléfono raros, DNIs complejos y anomalías que nunca pondrías tú a mano.

VELOCIDAD

Desarrollo Autónomo

Genera en segundos esquemas completos para no depender de otros equipos ni de bases de datos remotas.

TRAMPA
El error de crear 5 registros a mano en un archivo estático: En cuanto quieras probar paginación de 50 en 50, filtros combinados o estrés con concurrencia, tu aplicación parecerá que funciona pero colapsará en producción. Faker resuelve esto inyectando vida masiva.

🌍 i18n & Encodings

La Trampa de Occidente: Alfabetos que rompen Webs y APIs

El error clásico de desarrollo es probar solo con "Juan García". En producción internacional, las APIs y webs colapsan por problemas que Faker te permite anticipar:

RTL

Árabe (ar_SA) y Hebreo

Texto Right-to-Left. Invierte maquetaciones visuales, desborda formularios y rompe concatenaciones ingenuas sin soporte bidireccional (bidi).

UTF-8

Chino (zh_CN) y Multibyte

Ideogramas de 3-4 bytes. Si la base de datos usa codificaciones antiguas (latin1), genera Mojibake (????) y corrupción de datos.

LONGITUD

Validaciones Frágiles

Nombres chinos legítimos de 2 caracteres como "张伟" hacen explotar validaciones simplistas de tipo min_length=3 en Pydantic.

CIRÍLICO

Ruso (ru_RU) y Japonés

Caracteres no ASCII que rompen cabeceras HTTP, codificación en URLs (percent-encoding) y filtros de búsqueda por texto.

Faker Multilingüe: Rompiendo tu API con Árabe, Chino y Cirílico

python

# Generadores por localización idiomática

# Generador multilocale ponderado (dataset global y realista):

Datos de Dominio Específico: Automoción, Flotas de Vehículos y VIN

python 
import random
from faker import Faker

fake = Faker('es_ES')

def generar_evento_vehiculo():
    marcas_modelos = [
        ("Tesla", "Model 3", "Eléctrico"),
        ("Seat", "León", "Combustión"),
        ("Toyota", "Corolla", "Híbrido"),
        ("Renault", "Megane E-Tech", "Eléctrico"),
        ("Volvo", "XC60", "Híbrido Enchufable")
    ]
    marca, modelo, propuls = random.choice(marcas_modelos)
    
    return {
        # Bastidor oficial (17 caracteres alfanuméricos bajo ISO 3779)
        "vin": fake.vin(),
        # Matrícula española oficial (4 dígitos y 3 letras consonantes)
        "matricula": fake.bothify('#### ???').upper(),
        "marca": marca,
        "modelo": modelo,
        "tipo_propulsion": propuls,
        "conductor_asignado": fake.name(),
        "odometro_km": random.randint(15000, 185000),
        "velocidad_kmh": round(max(0.0, random.gauss(95.0, 18.0)), 1),
        "nivel_bateria_combustible_pct": random.randint(10, 100),
        # Códigos de diagnosis OBD-II estándar de averías
        "codigo_obd2": random.choices(
            ["P0000_OK", "P0420_CATALYST", "P0300_MISFIRE", "P0171_LEAN_BANK"],
            weights=[80, 10, 5, 5]
        )[0],
        "gps": {"lat": float(fake.latitude()), "lon": float(fake.longitude())},
        "timestamp": fake.date_time_between(start_date="-30m", end_date="now").isoformat()
    }

fake.vin() y fake.bothify() simulan flotas completas de vehículos conectados para analítica de Big Data.

Simulación de Sensores IoT para Smart City

python 
import random
from faker import Faker

fake = Faker('es_ES')

def generar_sensor_iot():
    ciudad = random.choice(['Alcoy', 'Valencia', 'Alicante', 'Castellón'])
    return {
        "sensor_id": f"SN-{ciudad[:3].upper()}-{fake.bothify('####')}",
        "ciudad": ciudad,
        "latitud": float(fake.latitude()),
        "longitud": float(fake.longitude()),
        "temperatura": round(random.gauss(mu=21.5, sigma=4.0), 1),  # Gaussiana
        "humedad": round(random.uniform(30.0, 95.0), 1),
        "co2_ppm": random.randint(380, 1100),
        "estado": random.choices(['OK', 'WARNING', 'CRITICAL'], weights=[85, 12, 3])[0],
        "timestamp": fake.date_time_between(start_date="-2h", end_date="now").isoformat()
    }

Combina distribuciones estadísticas reales con los generadores de texto de Faker.

PRO-TIP
El poder de las semillas (Seeds): Para que tus tests unitarios y pruebas de integración sean deterministas, usa Faker.seed(42). Generará datos que parecen aleatorios pero que serán exactamente los mismos en cada ejecución.

Modelando con Pydantic y Enums

python 
from pydantic import BaseModel, Field
from enum import Enum
from datetime import datetime

class EstadoSensor(str, Enum):
    OK = "OK"
    WARNING = "WARNING"
    CRITICAL = "CRITICAL"

class LecturaSensor(BaseModel):
    id: str = Field(..., description="UUID de la lectura")
    sensor_id: str = Field(..., description="Código del hardware")
    ciudad: str = Field(..., description="Municipio de instalación")
    temperatura: float = Field(..., ge=-20.0, le=60.0, description="ºC")
    humedad: float = Field(..., ge=0.0, le=100.0, description="%")
    co2_ppm: int = Field(..., ge=200, le=5000, description="PPM de CO2")
    estado: EstadoSensor
    timestamp: datetime

Pydantic valida tipos y rangos. Si Faker genera un valor absurdo, el modelo avisa de inmediato.

Endpoints de Consulta y de Inyección Masiva

python 
from fastapi import FastAPI, Query, status
from typing import List, Optional

app = FastAPI()
DATABASE: List[LecturaSensor] = [generar_sensor_iot() for _ in range(50)]

@app.get("/api/v1/telemetry", response_model=List[LecturaSensor])
async def get_telemetry(ciudad: Optional[str] = None, limit: int = Query(20, le=100)):
    res = [r for r in DATABASE if not ciudad or r.ciudad.lower() == ciudad.lower()]
    return res[:limit]

@app.post("/api/v1/simulate/burst", status_code=status.HTTP_201_CREATED)
async def simulate_burst(count: int = Query(10, le=200)):
    nuevas = [generar_sensor_iot() for _ in range(count)]
    DATABASE.extend(nuevas)
    return {"mensaje": f"{count} eventos inyectados", "total_almacenado": len(DATABASE)}

Los alumnos pueden simular ráfagas de 50 o 100 eventos con un solo clic en Swagger.

OJO
Listas en memoria vs Producción: Una lista global DATABASE = [] es perfecta para clase y prototipado rápido, pero se reinicia cada vez que reinicias uvicorn. En las siguientes unidades la reemplazaremos por Redis o PostgreSQL.

⚙️ ARQUITECTURA

¿Dónde se mete la Configuración Global en FastAPI?

Se define en el punto de entrada de tu aplicación (habitualmente main.py o app.py), directamente al crear la instancia del objeto principal app = FastAPI(...):

ENTRY

Instancia Única

Vive en main.py. Es el objeto raíz que luego arranca el servidor ASGI con uvicorn main:app --reload.

METADATOS

title, version y Markdown

La description admite Markdown completo (listas, negritas, enlaces) para documentar el propósito del sistema.

TAGS

openapi_tags

Agrupa y categoriza endpoints en carpetas visuales dentro de Swagger, con descripciones por módulo.

RUTAS

docs_url y contacto

Permite personalizar o desactivar /docs en producción y firmar la autoría del equipo de Big Data.

Configuración Global en main.py: Swagger Enterprise

python 
# main.py - Punto de entrada de la aplicación
from fastapi import FastAPI

# 1. Definimos los grupos temáticos (Tags) que organizan Swagger UI
tags_metadata = [
    {"name": "Telemetría IoT", "description": "Sensores urbanos y lecturas en tiempo real."},
    {"name": "Simulación Faker", "description": "Inyección masiva de eventos sintéticos para estrés."}
]

# 2. AQUÍ SE METE: Al instanciar 'app' con todos sus metadatos globales
app = FastAPI(
    title="CityData Streamer API 🏙️⚡",
    description="""
    ## Portal de Telemetría y Big Data Urbano
    API oficial para monitorización de flotas y sensores.
    * **Streaming**: Diseñado para alimentar Apache Kafka y Spark.
    * **Faker**: Generación sintética determinista sin riesgo de RGPD.
    """,
    version="1.2.0",
    openapi_tags=tags_metadata,
    contact={"name": "Equipo Big Data Batoi", "email": "bigdata@cipfpbatoi.es"},
    docs_url="/docs",       # Dónde se sirve la UI interactiva
    redoc_url="/redoc"      # Documentación alternativa de solo lectura
)

FastAPI compila estos metadatos en un esquema OpenAPI 3.1.0 estándar en /openapi.json.

💡 MECANISMO INTERNO

¿Por qué 'examples=[...]' aparece en Swagger?

Swagger UI no lee código Python directamente; existe una cadena de compilación de esquemas:

PIPELINE

Pydantic ➔ /openapi.json

FastAPI exporta tus modelos a JSON Schema (OpenAPI 3.1.0). El atributo examples=[...] se convierte en la clave estándar "examples": [...].

TRY IT OUT

Auto-rellenado Activo

Al pulsar 'Try it out', Swagger lee esos ejemplos y pre-rellena el formulario con datos creíbles en vez de un triste "string" o campos vacíos.

TRAMPA

default ≠ examples

default="X" hace el campo opcional. En cambio, Field(..., examples=["X"]) mantiene el campo OBLIGATORIO (...); el ejemplo es solo documentación.

v1 vs v2

Pydantic v1 vs v2

En Pydantic v1 era singular: example="X". En Pydantic v2 / OpenAPI 3.1 se usa una lista en plural: examples=["X", "Y"].

Implementación: Ejemplos de Campo y de Modelo Completo

python 
from pydantic import BaseModel, Field

class LecturaSensor(BaseModel):
    # '...' indica OBLIGATORIO. 'examples' es la muestra para Swagger:
    sensor_id: str = Field(
        ..., 
        description="Identificador único del hardware emisor", 
        examples=["SN-ALC-4091"]  # <-- Swagger lo usa para auto-rellenar
    )
    ciudad: str = Field(..., examples=["Alcoy", "Valencia"])
    temperatura: float = Field(..., ge=-20.0, le=60.0, examples=[21.4])
    co2_ppm: int = Field(..., examples=[420])

    # Ejemplo del objeto JSON COMPLETO para la documentación:
    model_config = {
        "json_schema_extra": {
            "examples": [
                {
                    "sensor_id": "SN-VAL-8821",
                    "ciudad": "Valencia",
                    "temperatura": 23.5,
                    "co2_ppm": 410
                }
            ]
        }
    }

Combina Field(..., examples=[...]) para cada propiedad y json_schema_extra para el JSON global.

¡CUIDADO!
El error de novato: default vs examples. Si pones ciudad: str = "Alcoy", el cliente puede omitir el campo y la API lo aceptará con ese valor por defecto. Si pones ciudad: str = Field(..., examples=["Alcoy"]), el campo sigue siendo estrictamente obligatorio; el valor solo sirve de guía para quien prueba la API en Swagger.
